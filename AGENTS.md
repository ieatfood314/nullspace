# Notes for coding agents

The README covers what Nullspace does and how the data looks. This file covers where it runs and how it ships. Install-specific facts (addresses, ports on the tailnet) are in the fleet skill, not here; this repo is public.

Nullspace was called Uplink until November 2026, and Uplink is gone: everything on Aidan's machines and in the code says Nullspace (renamed 2026-11-19). What keeps the old name, because changing it would make Android treat the app as a new one (no update in place, lost data and permissions): the `applicationId` and package `ca.heeney.uplink`, `UplinkService` (the accessibility service's class, which the phone's settings name), the intent actions under the package, the phone's own files (`uplink.db`, the `uplink` prefs file) and the signing key's alias. For people who set a hub up before the rename, the hub still reads `UPLINK_*` variables (`NULLSPACE_*` wins) and `~/.local/share/uplink/`, Gradle still finds the key in `~/.config/uplink/`, and the page moves its `uplink-*` localStorage keys over once.

## Dictation speed
Transcription must never take more than 1 second per 50 words, on every device: halley, mars and regolith alike. Aidan set this rule on 2026-11-19, after Nullspace made dictation feel slower than Squelch. Check it in the logs (`transcribed in Xs` from squelch-ptt and the parakeet server; on the phone, logcat with the dictation's length). Anything that runs between letting go of the key and the text going in (tidying, guessing a cut-off start) gets a hard deadline and is skipped when it misses it: the phone gives both 1 s in all (`POLISH_MS`), and squelch-ptt's guess-start gets 0.6 s (`GUESS_WAIT_S`). A change that makes dictation slower needs Aidan's OK first.

## Branches and releases
Nullspace has users besides Aidan, so experiments must not reach them.

- **`main` is the testing branch.** All work lands here, as before: branch off it, merge back into it. Aidan's hub runs it, and his phone gets it as a testing build.
- **`stable` is what users get.** It only ever fast-forwards to a commit of `main` that has been on Aidan's phone for a while with no problems: `git push origin <commit>:stable`, never a commit made on `stable` itself. A fix that's urgent for users goes to `main` first, then `stable` moves up to it.
- **Releases:** `android/release.sh "notes"` (on `main`) publishes a GitHub pre-release. `android/release.sh --stable` (on `stable`) marks that same build as the full release, so the version doesn't change. Obtainium only offers pre-releases when "include pre-releases" is on (Aidan's is). The hub has no releases: users run `stable` from git.
- **Keep `stable` moving.** You're in charge of this. Whenever you merge to `main`, check how far `stable` is behind (`git log --oneline origin/stable..origin/main`). If the newest testing build is at least two days old and Aidan hasn't reported trouble with it, promote it, then tell him you did. Don't let `stable` fall more than about two weeks behind `main` without asking him why.
- **No forgotten changes.** Before you end a session, run `git status` in your worktree and in `~/repos/nullspace`. Commit what you made (on your branch, or `main` if Aidan asked for it), or list it under "Parked work" below with what it is and why it's waiting. Uncommitted edits in someone's checkout are invisible to every other session.

## Where things run
- **Repo:** `~/repos/nullspace` on nas (T3 project "Nullspace"; it was `~/repos/uplink` until 2026-11-19, and older worktrees under `~/.t3/worktrees/uplink/` still point at it through `git worktree repair`). GitHub: `ieatfood314/nullspace` (the old `ieatfood314/uplink` URL redirects there).
- **Hub:** the `nullspace` user unit on nas, a copy of `systemd/nullspace.service` pointed at `server/nullspace.py` in the repo, so a change ships with `systemctl --user restart nullspace`. Config is in `~/.config/nullspace/hub.env`, and data is in `~/.local/share/nullspace/` (SQLite plus `shots/`).
- **Test hubs:** run a second hub on a copy of the data so it never touches the live one: `python3 server/nullspace.py --port 4698 --data /tmp/<copy>` (copy `hub.db` with `sqlite3 hub.db ".backup /tmp/<copy>/hub.db"`). Start it from a small script that sources `hub.env`, not inline, and kill it with a bracketed pattern in a command of its own (`pkill -f 'nullspace.py --por[t] 4698'`): a pkill in the same command line as the start matches your own shell. The hub used to mirror tasks into Radicale (for tasks.org) and Ignition; both bridges were removed in November 2026, and Nullspace is now the only copy of the list.
- **LLM:** the free pool on nas (`NULLSPACE_LLM_URL`, `NULLSPACE_LLM_MODELS=free,free-fast` and the client key in `hub.env`; the fleet skill's free-pool file has its providers and limits). When no provider answers, the plain parser files captures, and Redo on a capture tries again. OpenCode Zen's free models refuse non-OpenCode clients, so don't switch to them. `free-fast` can land on a reasoning model (gpt-oss), which spends ~150 tokens thinking before it answers, so give short calls a token budget with room for that. Tidying and guessing a cut-off start don't use the pool: the phone waits at most 1 s for them (`POLISH_MS`), then puts the text in as heard, and the pool can take 2 s or more when Groq is busy and it falls back. They go to Groq direct instead (`NULLSPACE_FAST_LLM_URL/MODEL/KEY_FILE` in `hub.env`, `qwen/qwen3.8-27b`, about 0.2 s), and the phone's own-key path uses the same model when its key is Groq. Groq's Cloudflare front refuses Python's default User-Agent (error 1010), so the hub sends its own.
- **Categories:** the hub picks each open task's category. With a TypeSafe key in `~/.config/nullspace/typesafe_key` (`NULLSPACE_TYPESAFE_KEY_FILE` in `hub.env` points at it) it asks Jev, one request per task. Without that file it asks the filing LLM about all waiting tasks in one request, at most every 5 minutes. The key file is read on every use, but the engine's thread only starts at boot if there is some key, so restart the hub after adding the first one. The TypeSafe console blocks automated browsers (Cloudflare), so only Aidan can make that key.

## Standalone and the hub: two filers, kept in step
With no hub set, the phone files captures itself: `Filer.kt` (the hub's `Processor`), `Plain.kt` (the hub's `basic_parse`, `settle`, `roll`, `tidy_repeats` and their helpers), `Brain.kt` (the hub's prompts, sent to the user's own key; Groq by default), `Categories.kt`, and `Geo.kt` (Nominatim, for address search). They are ports of `server/nullspace.py`. When you change filing on one side, change the other the same way:

- Prompts (`PROMPT`, `GUESS_PROMPT`, `TIDY_PROMPT`) are copied word for word; regenerate the Kotlin strings from the Python ones rather than editing both by hand.
- `server/plain_cases.py` runs the Python parser over a set of phrases, LLM answers, split repeats and rolls at pinned times and writes `android/app/src/test/resources/plain-cases.json`; `PlainTest` replays it against `Plain.kt`. After changing either side, add cases for it, run `python3 server/plain_cases.py`, then the phone's unit tests (below). A failure there means the two drifted apart.
- Dictation tidying and cut-off guessing go to the user's own key if there is one, else to the hub (`/api/tidy`, `/api/guess-start`), else are skipped.

## Android
- **Build on regolith, not nas.** Gradle and the emulator starve nas (7.7 GB RAM), and a Gradle run on nas was OOM-killed. rsync `android/` and `web/` to a folder of your own under `regolith:build/` (exclude `build`, `.gradle`, `local.properties`, `app/libs`), then `ssh regolith 'cd ~/build/<yours>/android && nice -n 15 ./build.sh'`. Other sessions' `build.sh` runs `gradlew --stop`, which kills every daemon of that user, failing your build with "Gradle build daemon has been stopped: stop command received". Avoid it with a Gradle home of your own: copy `~/.gradle/wrapper` and `~/.gradle/caches/modules-2` into, say, `~/.gradle-<yours>` once, and run Gradle with `GRADLE_USER_HOME` pointing there (plus `JAVA_HOME=$HOME/.local/android-toolchain/jdk17 ANDROID_HOME=$HOME/.local/android-toolchain/sdk`). The signing key and `android.properties` are in `~/.config/nullspace/` on both hosts. regolith's copy has `storeFile` under `/home/aidan-heeney`.
- **Unit tests** (JVM, no device): `./gradlew testReleaseUnitTest`. `PlainTest` (the parity check above), `RepeatTest`, `EditWatchTest`, `SpacingTest` (the spaces around a dictation, with cursor offsets recorded from Obsidian), `CleanupTest` (local disfluency) and `CorrectionsTest` (contextual correction learning).
- **Emulator:** AVD `sq35` on regolith, started headless (`-no-window`), so nothing pops up on Aidan's desktop. Point a build at a test hub with `-Phub=http://10.0.2.2:<port>` and an `ssh -R` tunnel. The emulator isn't a Nothing phone, so the key starts as the volume keys (`sendevent /dev/input/event1 1 114|115 1|0` for down and up, with `adb root` first); to fake the Essential key instead, set prefs `key_code=0` and `scan_code=88` and send code 88. The power-button menu: `cmd role add-role-holder android.app.role.ASSISTANT ca.heeney.uplink`, `settings put global power_button_long_press 5`, then `input keyevent --longpress KEYCODE_POWER`. Don't use `uiautomator dump` while testing the overlays: it reconnects every accessibility service, which drops Nullspace's menu and card; tap by coordinates from a screenshot. regolith's zsh doesn't word-split `$A`, so use a wrapper script for adb. Anything that dictates needs `./build.sh -Pemu`: the release APK is arm64-only, and onnxruntime segfaults under the emulator's ARM translation. A real dictation on the emulator also syncs its stats to the live Squelch hub, so delete that device's `stats/<id>.jsonl` and its `devices.json` entry afterwards (stop the hub first, since it holds them in memory). Stop the emulator before you do, because the Words sync re-adds the device even with no dictations. If a test script replaces the app's prefs file, keep `<string name="model">` in it (the emulator has `parakeet-tdt-110m-en`); without it the app falls back to a model that isn't installed, and every hold silently does nothing.
- **Tests on the emulator:** `android/test.sh` runs `app/src/androidTest` (the Tasks tab in the real WebView: the three views, the task sheet, the back key) and leaves screenshots in `app/build/outputs/connected_android_test_additional_output/`. Run it against the AVD `nullspace-test` on regolith, not `sq35`: Gradle removes the app and its data from the device it tested on, which on `sq35` would take the downloaded model with it. Start it headless on its own port (`emulator -avd nullspace-test -no-window -no-audio -no-boot-anim -no-snapshot -memory 2048 -port 5556`, under `systemd-run --user` so it outlives the ssh call), then `ANDROID_SERIAL=emulator-5556 nice -n 15 ./test.sh`, and stop the unit afterwards. The tests seed their own tasks and run with both hubs switched off (`OfflineRunner`), so they never touch real data.
- **The page is `web/`,** copied into the APK at build time. Change it once and both the hub and the phone get it. The phone loads it from `https://appassets.androidplatform.net/web/` and talks to the native side through `NullspaceNative` (which also answers address search and Redo on the phone when there's no hub, and gives the page the accent color).
- **Mobile data budget:** a monthly cap the user sets (Settings, Mobile data; `Prefs.dataCapMb`, 10 MB by default, and 10 MB is Aidan's hard rule for his own phone). Anything new that talks to the network has to go through `HubSync.post` (which counts it and refuses past 95% of the cap) and skip big transfers when `Net.metered`.
- **Training data:** two queues in `Archive.kt`. "Keep recordings" sends to the user's own Squelch hub (on by default only in builds with a `squelch_hub`). "Share training data" sends to the project at `donate_url` from `android.properties`; it is opt-in, off by default, hidden in builds without a `donate_url`, never includes the text that was already in the box, and turning it off deletes what was waiting. Keep it that way: sharing must never be on unless the user turned it on.

## Desktop
`desktop/nullspace-desktop` is Nullspace for Linux (PyQt6, KDE Plasma on Wayland): the tray icon, the window (the hub's page in QtWebEngine), the screenshot card, voice notes and reminders. It doesn't read the key: Squelch's `squelch-ptt` does, and while this app's socket (`$XDG_RUNTIME_DIR/nullspace-<uid>`) answers, it turns taps into lines on it: `capture`, `open`, `note-start {"about": uid|null}` and `note-end {"about", "text"}`. `<socket>-card` holds the uid of the screenshot whose card is showing, so a hold then is a note about it. squelch-tray hides its icon and ignores taps while the socket answers. Change that protocol on both sides (Squelch's `Gestures`, `note_for` and `end_note`).

- Captures go to the hub in Settings over `/api/sync` and `/api/shot/<uid>`, in the phone's record format (`device: "desktop"`); with no hub set it starts `nullspace-hub` (the hub, installed under `/usr/lib/nullspace`). Records waiting to go are kept in `~/.local/state/nullspace/`.
- Reminders are only shown, never marked fired, so the phone still rings.
- **Settings** is one screen like the phone's: `desktop/settings.html` in the window (in place of the hub's page; installed to `/usr/lib/nullspace/desktop/`), answered by `Bridge` over QWebChannel. Its rows follow `SettingsActivity.kt`, so add a setting to both. Dictation's rows read and write Squelch's own files through squelch-tray's helpers (the app loads `squelch-tray` as a module), so there is no second settings window; a renamed helper in Squelch breaks them, so check `Bridge` when bumping `_squelch`. The AI key goes to the local hub (`hub.env`) and to squelch-ptt's `llm-fast.json` for guess-start, unless that file points at some other key. To test it without touching real config, run the app under `QT_QPA_PLATFORM=offscreen` with `HOME`, `XDG_*` and `XDG_RUNTIME_DIR` pointed at a temp copy of `~/.config/squelch` and `w.grab()` screenshots; link `~/.local/share/fonts` in for the fonts and set `PIPEWIRE_RUNTIME_DIR=/run/user/1000` for the microphone list.
- **Shipping:** the AUR package `nullspace` (`desktop/PKGBUILD`), built from `desktop-vX.Y.Z` tags (the phone's releases are `v1.0.<n>`, so the two never collide). It carries Squelch's engine and replaces the `squelch` package (provides/conflicts): the PKGBUILD pins a Squelch tag in `_squelch`, builds whisper.cpp like Squelch's PKGBUILD and installs the engine with Squelch's `packaging/install-engine --no-launcher`, so keep its depends and whisper.cpp commit in step with Squelch's. Like Squelch: bump `pkgver`, tag `desktop-vX.Y.Z` on `main` and push it, put the tarball's sha256 in PKGBUILD, make `.SRCINFO` on regolith (`makepkg --printsrcinfo`; nas has no makepkg), commit both under `desktop/`, then push PKGBUILD and .SRCINFO to `ssh://aur@aur.archlinux.org/nullspace.git` from regolith (only its key can). Install on regolith with `makepkg` (several minutes, it builds whisper.cpp) and `sudo -n pacman -U --noconfirm --ask 4` (4 answers yes to removing `squelch`), then `systemctl --user daemon-reload` and restart squelch-vram, squelch-ptt, squelch-tray, squelch-ydotoold and nullspace-desktop; mars goes through the fleet skill's when-online queue, like Squelch's packages (`/mnt/RAID1/Aidan/squelch-pkg/`). A change to squelch-ptt's side needs a Squelch release first, then `_squelch` bumped here and a Nullspace release.
- **The desktop's stable channel is the AUR tag, not `stable`.** `stable` predates the desktop app, so AUR users get `main` as of each `desktop-v` tag, the bundled hub and page included. A desktop fix reaches users through a desktop release, not by moving `stable`. Before tagging, check `git diff --stat desktop-v<last> main -- desktop server web`: that is everything the release changes for desktop users, and phone or hub experiments in it ship to them too.
- **Testing** on regolith without touching Aidan's session: a nested `kwin_wayland --virtual` under `dbus-run-session`, with `XDG_RUNTIME_DIR` (and the app's config, state and data dirs) pointed at a temp folder from the very start, so the real Squelch never sees its socket, and `WAYLAND_DISPLAY` an absolute path to the nested socket. Never let anything in the nested session run with `XDG_RUNTIME_DIR=/run/user/1000`, KWin included: its private bus activates an a11y launcher there, which replaces the real session's `at-spi/bus_0` and leaves it dead when the test ends, and every AT-SPI client started afterwards (squelch-ptt included) can't reach it (`systemctl --user restart at-spi-dbus-bus` repairs it). Start `/usr/lib/at-spi-bus-launcher --launch-immediately` and `/usr/lib/at-spi2-registryd` in it for screen text (D-Bus activation of them fails on a private bus), and send the socket lines by hand. The first Spectacle run after changing `XDG_DATA_HOME` takes seconds (KDE rebuilds its cache), and two Spectacles at once hang.

## Squelch
Nullspace replaced Squelch for Android (same dictation code, forked from `squelch/android`). On the desktop Squelch is both its own product (dictation only, AUR `squelch`) and Nullspace's speech engine (the `nullspace` package carries it and replaces `squelch`, and with Nullspace installed the engine calls itself Nullspace wherever people see it); they are promoted separately. When dictation changes in Squelch (cleanup rules, the dictionary format, guess-start, the archive or corrections format), carry the change over to Nullspace's `Dictation.kt`, `Cleanup.kt`, `Words.kt`, `EditWatch.kt` and `Archive.kt`. Nullspace's Words sync talks to the Squelch hub (`/v1/sync`, `/v1/archive`, `/v1/corrections`), Wi-Fi only; Squelch's README documents that side.
